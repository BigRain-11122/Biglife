# 居民智能体底座 v0（Agent Kernel）— 设计契约 2026-11-21

目的：给每个硅基居民一个**统一的认知内核**，而不是一堆散在 `evolve_citizen.build_prompt`
里的临时计算。内核只做四件事（对齐 Generative Agents 的 observation→reflection→planning），
其余（文笔、闸、产出配额）都留在外层。

## 一、内核四段与现有零件对照

| 段 | 职责 | 现有零件 | 缺口 |
|---|---|---|---|
| **O 观察** | 今天"我看见了什么"：城市事件（按在场 zone 过滤）、天气、他人的相遇 | 事件流带 zone；居民有城区 | **缺在场过滤**（现在全城事件人人可见） |
| **M 记忆** | 长期经历 + 重要度 + 检索 | `memory_stream.py`（recency×importance×relevance） | importance 是关键词代理；缺"在场"权重 |
| **R 反思** | 把多段经历综合成更高层判断 | `reflect_step`（50–160 字第一人称，须含"我不再…而是…"） | 配额未跑满（67/900） |
| **P 计划** | 此刻该做什么、目标推进到哪 | `goals`（按日历涨＝假）、`agency`（每日意图，未进提示词） | **进度不真**、无日程（这个点该在哪） |

## 二、内核接口（后续所有改动只走这五个函数）

```
agent_state(cid)            -> dict   读持久状态（情绪/目标进度/关系强度/在场）
agent_observe(cid, day)     -> list   当天"我在场"的事件（zone 匹配）
agent_recall(cid, ctx, k)   -> list   按记忆公式取 k 条（memory_stream 包装）
agent_reflect_due(cid, day) -> bool   是否需要反思（重要度累积 + 冷却）
agent_plan(cid, day)        -> dict   此刻该在哪、这周想做什么、目标下一小步
```

约束：
- **全部零 LLM**（除反思/年轮文本本身），保证每轮 1 万居民可算；
- 状态落 `state/agent/<cid>.json`，只增不改历史（可回滚）；
- 任何一段缺失返回空值，**prompt 零漂移**，绝不阻断产出。

## 三、落地顺序（每步都有可测验收）

| 步 | 做什么 | 验收 |
|---|---|---|
| 1 | **在场过滤**：事件按 zone 过滤进 O 段 | 同一天不同城区居民引用的具体事重合率 <20% |
| 2 | **日程**：`agent_plan` 返回"此刻在哪儿/在做什么" | 抽 30 人：年轮里的地点与日程一致率 ≥80% |
| 3 | **目标真推进**：年轮写出推进才 +1，卡住可回退，长期不动则失败换新 | 进度与内容一致率 ≥80%；能看到"放弃"案例 |
| 4 | **关系强度**：0–100，相遇 +、砍价 −，影响措辞冷热 | 强弱两组措辞的词面差异可测 |
| 5 | **反思跑满**：900/天 | ALIVE.md 里反思条数达标 |

## 四、底座与外层的边界（不越界）

- 内核**不写文案**、不做闸、不做配额，只提供"这段日子对这个人意味着什么"。
- 外层（evolve/pump/scheduler）继续管产出与质量；内核坏了必须**降级不阻断**。
- 与游戏车道共用同一模型、排队（`resource_policy`），不新增显存占用。

## 五、现在就要下的第一刀

**第 1 步（在场过滤）**：改动最小、收益最大——它同时修掉"全城都知道一切"和
"每个人讲的事都差不多"两个老毛病。做完再动日程与目标。
