# 借鉴：Steam 上「会过日子的 NPC」四款，可直接借的数据形态

> 只借**数据结构与判定逻辑**，不搬内容、不搬美术。数值细节标注【待核】的，
> 是凭公开 wiki 的结构记得、具体数字没当场核过——用前必须核，别当事实引。

## 一、四款各自最值得拿的那一块

| 游戏 | 借什么 | 为什么它最值 |
|---|---|---|
| **Stardew Valley** | **NPC 日程表**：按（季节/星期/时间/天气）→ 所在地点 + 行为 | 它有"这个点这个人在哪"的完整表，而且天气/节日会改写日程——正是我们缺的"时钟" |
| **RimWorld** | **Thought/Opinion 模型**：事件 → 加/减心情值 → 多条叠加 → 影响行为 | 它的"态度"是**可累加的数值**，不是标签；这正好补我们关系只有标签的问题 |
| **Dwarf Fortress** | **personality facets（几十个连续维度）+ 生成式人生史** | 个体差异来自连续维度组合，不是抽短语；这解释了我们"固定池"路线为什么读起来假 |
| **The Sims** | **motive 衰减曲线**：需求随小时下降，驱动行为选择 | 我们已有四轴需求（安身/生计/社交/好奇）但没有"随时间衰减"，所以需求不推着人走 |

## 二、四份可直接借的数据形态

### 1. 日程（Stardew 式）
```
(cid, 星期/季节/天气, 起止小时) → {地点, 行为, 前置条件}
```
落到我们：`agent_plan(cid, day)` 返回值里加 `where`/`what`；年轮里"这个点儿我在摊上"必须来自这里，
不是每轮随机。**判据**：抽 30 人，年轮地点与日程一致率 ≥80%。

### 2. 心情值（RimWorld 式）
```
事件 → thought(def, 偏移值, 持续小时) → 叠加求和 → mood 分档 → 影响措辞与选择
```
落到我们：现在的"情绪"没有数值。加 `mood`（-100..100），相遇 +、砍价 −、被插话 −，
过期自动衰减。**判据**：强弱两组措辞的词面差异可测（冷/热词频）。

### 3. 人格连续维度（DF 式）
```
facets: 0..100 的若干连续轴（如 慷慨/急躁/顺从/好奇…），由 cid 确定性派生
```
落到我们：现在的"性格"是三枚标签（清旧账/较真/把关），读起来像抽卡。
改成 5–8 个连续轴，措辞与取景由轴值加权决定。**判据**：同职业同年龄、轴不同的两人，
年轮开头句式相似度 <0.5。

### 4. 需求衰减（Sims 式）
```
need(t+1) = clamp(need(t) - decay*dt + 满足事件)
```
落到我们：四轴需求目前是静态派生。加衰减后，"饿了/缺钱/闷得慌"会**随着日子累积**，
自然产生摩擦——正好补今天测出的摩擦率 48%（目标 65%）。

## 三、Steam 侧的"直接拿来用"边界

- **可借**：数据形态、数值设计思路、公开 wiki 的机制表、开源同类项目的代码结构。
- **不可借**：美术/音频/文本内容、有版权的名词与专有设定（L1 许可红线）。
- **可核来源**：Dwarf Fortress 官方免费版（Bay 12）、RimWorld 的 Defs XML（模改公开）、
  Stardew 的 wiki 日程页、The Sims 的 motive 说明。**取不到就标【待核】，不编数字。**

## 四、与我们路线的合并（不新增战线）

优先级：**需求衰减（最便宜，直击摩擦率）→ 日程 → 心情值 → 人格连续轴**。
前两项能在一周内落到 `agent_plan` 与四轴需求里；后两项要动提示词与数据迁移，排在后面。
