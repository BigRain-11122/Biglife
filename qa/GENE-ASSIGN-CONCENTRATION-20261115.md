## 一、待解释的现象

`Tools/build_gene_ledger.py` 长期报 `habits: 28/124`（在册 28 条、登记 124 条、未落册 96 条），
被今晨一轮判为「复读结构性根因」：单条习惯「初一必清一次柜顶」被 141 名居民共享，
即万人规模下每种子承载数百人，同日子集必然撞句。

**待查三问**：①分配函数是否偏斜；②为何只有 28/124 在用；③集中度指标能否进 QC。

### 断言 A：卡面里命中的习惯索引是连续切片，不是哈希散布

逐条比对 `genes/lives.json` 的 habits 与 `census/registry/*/*.md` 正文，命中的索引为
**0,1,2,…,27 恰好 28 条连续前段**。哈希取模不可能产出连续前段，只可能是**顺序切片**。

### 断言 B：卡面根本没有习惯字段，命中来自「行为」段注脚

- 10091 张户卡中只有 **15 张**正文出现「习惯」二字，且全部是年轮里的口语（「真不太习惯」「还是这习惯」），
  没有一张有「习惯」字段。
- 28 条习惯的命中落点是 `**行为**` 段（例：`census/registry/GM/C-00069.md` 第 17 行
  「改一件配三套方案，纠结症晚期但成品零差评；每天给阳台的花说一句话；收摊前必把明天的料先备好。」）。
- 28 条习惯合计命中 **18962 次 / 10091 张卡**（每条 635–725 张），即写卡当时每居民抽 1–2 条，
  抽的池子是 **28 条的快照**。
- 根因：户卡自 2026-09-30 `REGISTRY-FROZEN` 后不再重写。lives.json 的 habits 此后经基因轮
  从 28 条增补到 124 条，新增 96 条**永远不会**出现在冻结卡面。

### 断言 C：分配函数本体是均匀 md5 取模

`Tools/persona_enrich.py:32`

```python
def pick(cid, salt, seq):
    return seq[h32(cid, salt) % len(seq)]      # h32 = md5(cid + "#" + salt) 前 10 位十六进制
```

池子 = `persona-v2.json`(15) ∪ `lives.json`(124)，装池时按序去重并集（同文件 `load_genes()`）。
每居民必抽 1 条（盐 `hb`），`h32(cid,"hb2") % 3 == 0` 时再抽第 2 条（盐 `hb2`）。
无排序偏好、无前 N 条特判。

### 断言 D：活面分布近均匀

`census/export/citizen-persona.jsonl`（10114 行、13506 次抽取）：

| 指标 | 实测 | 均匀理想 |
|---|---|---|
| 在用条目 | 126 / 139（含 v2 池 15 条） | 139 |
| 每条期望 | 97.1 次 | 97.1 |
| 实抽区间 | 53 – 184 次 | — |
| 头名占比 | 1.36% | 0.72% |

头名占比 1.36% 对 190 桶量级属正常抽样噪声（sd≈9.8，区间 53–184 落在 ±4σ 边缘），
不支持「分配器结构性偏斜」。

## 三、结论（三问三答）

1. **分配函数无偏斜**：md5 取模、无前段特判，活面头名占比 1.36%（理想 0.72%），
   未达到「单种子被系统性偏爱」的形态。今日 9-gram 首位复读的「初一清柜顶」族，
   源于**早期池只有 28 条**时的历史分配（每条 → 360+ 人），不是当前分配器造出来的。
2. **28/124 是口径错配，不是分配缺陷**：
   - 28 = 冻结卡面快照时代的池长度（顺序切片 0..27）；
   - 124 = 今日登记数；
   - 分母（10091 张冻结卡）与分子（活分配）根本不同源，这个比值对分配健康度**零信息量**。
3. **集中度指标应进 QC，且必须取活面口径**：已落地 `census/export/gene-live-coverage.json`。

## 四、修法（不改既有卡、不改阈值）

1. **口径修正（已实施）**：`build_gene_ledger.py` 新增活面承载统计——
   - HTML 缺口选题单的「习惯」节追加 `· 活面在用 113/124（分配 12035 次 · 均值 97.1 · 头名占比 1.53%）`；
   - 落盘 `census/export/gene-live-coverage.json`（字段：`live_used / live_zero / top1_share /
     expected_per_bucket / persona_rows / registry_frozen`），供 QC 直接取用，不再读冻结卡面。
   - 双跑确定性与原页字节一致（MD5 比对 PASS）。
2. **分配器不改**：既证否偏斜，改它就是无因改代码。
3. **11 条零桶不是缺陷，是滞后**：零桶索引恰为 `113..123`（lives.json 末尾最新并入的 11 条），
   `lives.json` mtime 08:53 vs `citizen-persona.jsonl` mtime 00:06 —— persona 面尚未重跑。
   **注意**：`pick()` 用 `len(seq)` 取模，池长变化会让**全部 10114 名居民的既有习惯重排**；
   这属内容连续性决定，不作例行修复动作，留待专门决策（已记 T-20261115-02 观察位）。
