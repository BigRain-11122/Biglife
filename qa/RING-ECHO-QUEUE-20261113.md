# 年轮检测盲区 + 修复队列饿死（R2761·2026-11-13）

零 LLM·确定性。工具 `Tools/ring_simile_audit.py`。

## 病根一：示例原句照抄在检测面是盲区

出生站闸（`evolve_citizen.py` v0.6x）只比对**开头 16 字**的示例原句，正文中段照抄的老环
全部漏过；而质检三判据（sim / short / tmpl）也一条都抓不到（示例句 7 字，够不上 10 字
模板窗口，也不构成相邻复读）。结果：库里 99 圈正文含提示词示例原句，质检看不见、
修复队列收不到、CEO 品质面也不显示。

实测（2026-11-13）：`grep 账本翻到第三页|锅底又薄` = 112 行命中 / 99 圈（13 行同圈含两句，
Select-String 按 pattern 重复计数），独立按 `^- YYYY-MM-DD` 复算 = 17063 环中 99 环，两法一致。

## 病根二：修复队列被旧积压饿死

队列按严重度权重排序后硬截断 400 席。示例原句环若只按 tmpl 计权（=1），排在所有权重 ≥2
的旧环之后；实测修改前**当日 552 环 0 条入队**、示例原句环 0 条入队——最新生产日的缺陷
永远排不到修复席位，等于修不上。

## 修法（两件，均在本文件内）

1. 新增判据 `echo`：直接 import `evolve_citizen.PROMPT_EXAMPLE_ECHO`（判据单源，禁重抄，
   同 `ring_material_check` 取 `RUMOR_TRIGGERS` 的纪律）；正文全文匹配，不只看开头。
   权重 8（最高档，逐字照抄示例 = 最坏一类）。装载失败时报告显式写「未装载」，
   不静默算绿。
2. 队列新增**新近保底**：近 `RECENT_DAYS=3` 日缺陷保留半数席（`QUEUE_CAP//2`），
   其余按严重度补齐；队内次序仍按权重，`quality_queue_order()` 的 rank 语义不变。
