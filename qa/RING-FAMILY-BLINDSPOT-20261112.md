# 开头族分类盲区修复（R2608 · 2026-11-12）

## 缺陷
`Tools/ring_open_family.py` 的 HAND_DEICTIC 族只认 `^手上的`（要求「的」）/
`^手在` / `^手心`… / `^我正`，而族定义本文写的是「手部指示+第一人称进行时骨架
（手在X／手上的X／我正把X）」。实测今日 467 条年轮开头里有 **49 条同形但不同助词**
的起句完全逃过配额闸（不计入、不拒绝、不提示）：

```
x2  手上这件还没收尾——数据…
x1  手边那截旧护缆又该上油了
x1  手边的面板还亮着，风扑在…
x1  手边这几样我都过了一遍，…
x8  我把手边的<物件>往边上…（同一骨架被照抄 8 次）
```

即：闸的读数（42.8%）低于真实值，且提示词仍在把落在这个盲区的骨架发给居民
（24 条骨架中有 4 条：`手上这件…`、`手边这几样…`、`我把手边的…`、`我把手头的…`）。
这是 R2588「闸与提示词自相矛盾」的同族第二面：第一面是提示词教模型写被禁形状，
这一面是闸看不见的族形状反而被提示词主动喂出去。

## 修法（三处同源，缺一即再犯）
1. `Tools/ring_open_family.py` HAND_DEICTIC 模式：`^手上的` → `^手上`，
   新增 `^手边`、`^手头`、`^我把手[边头上下]`（全部 `^` 锚定开头，句中合法
   身体描写不受影响）。**属补全既有族定义，非新增族**——族说明本文早已写「手上的X」。
2. `Tools/evolve_citizen.py` `FAMILY_OPEN_HINTS["HAND_DEICTIC"]` 同步点名
   「手边」「手头」「我把手边」「我把手头」，使硬闸拒绝的形状与提示词告知的形状一致
   （`family_blk` 直接取该表，故硬约束段自动更新）。
3. 骨架过滤无需改动：`opening_seed_block` 已用 `_ring_family_of` 过滤，模型真值表
   修正后 4 条盲区骨架自动退出今夜发放池。

## 诚实边界
- 只改**判据真值表与提示词**，未改「拒稿/放行」判定的阈值（配额 25% 不动）、未改配额算法。
- 读数从 42.8% 升到 55.0% 不是产出变差，是**过去漏计 57 条**；同一批已落环文本不回溯改写。
- 本轮在让路窗内，零 LLM：**不证**今晚文本变好，只证「闸看得见的形状 = 提示词被告知的形状」。
- 遗留盲区（未收口，避免过度加宽）：`我把手头…`（已被 `^我把手[边头上下]` 覆盖）之外的
  泛化「我把+物件」形态仍归 OTHER——加宽到 `^我把` 会误伤大量正常第一人称起句，
  无数据支持，故不动。
