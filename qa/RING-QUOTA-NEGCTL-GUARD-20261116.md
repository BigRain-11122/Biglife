## 一、为什么要加这道闸

R3208 实锤：全城吸引子「这会儿手边最碍事的就是这」末次被拒 07:34，`REFUSAL_BAN_HOURS=12`
→ 19:34 到期，而年轮生成窗 19:00 就开。原负控台按「A 臂跑完 → 打补丁 → B 臂跑完」顺序执行，
只判三条硬线（落环/命中率/复读面），**不记录两臂起跑时的禁牌集合**。

后果：若 A 臂落在禁牌生效期、B 臂落在解禁后，两臂之差里混进了「禁牌到期」这一整块，
量到的不是补丁效果。此时无论判 PASS 还是 FAIL，都不可用于决定补丁留撤。

## 二、改法（只加观测与判据，不动任何闸阈值/族表）

1. `ban_snapshot()`：复用 `evolve_citizen.recent_refusal_bans()`（不复制阈值），返回
   `{n, keys, exp_min, exp_max}`，拿不到时返回 None（降级不阻塞实弹）。
2. 两臂各自起跑前各取一次快照（`snap_a` / `snap_b`）。
3. `judge()` 先过混淆面：
   - `expired = keys_a - keys_b` 非空 → **CONFOUNDED**，直接判无效，不给留撤结论；
     （时间漂移：禁牌在两臂之间到期）
   - `added = keys_b - keys_a` 非空 → **携带效应**，只记注不误杀——A 臂被拒的开口会进
     禁牌表，B 臂因此更受限，偏差方向对 B 不利，故 PASS 仍可信、FAIL 需重跑确认。
4. `write_report()` 增禁牌态一行；`--dry-run` 输出当日禁牌数与最早/最晚到期点，
   并提示「两臂须连跑且不跨到期点」。
