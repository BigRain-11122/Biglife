# 年轮结构性饥饿定谳与修复（R2794·2026-11-13）

## 一、现象
CEO 面长期反映「产出落地很少」。此前归因为「产能不足」，本轮实测证明**产能之外还有一层分配缺陷**：
每天 ~550 席的年轮预算，几乎全部被低编号段居民的 7 日冷却循环吃掉，高编号段居民**从未轮到**。

## 二、实测证据（均可复跑）
数据面：`state/evolve-cursor.json`（10114 条），今日 `2026-11-13`。

| 编号段 | 到期/该段总数 | 到期占比 |
|---|---|---|
| 0–1999 | 1148 / 1993 | 57.6% |
| 2000–4999 | 2802 / 3000 | 93.4% |
| **5000–7999** | **3000 / 3000** | **100.0%** |
| 8000–9999 | 1868 / 2000 | 93.4% |
| 合计 | 8818 / 10114 | 87.2% |

最久未演化样本：`C-04166` 组（C-04166…C-04181）**last=2026-09-29，next=2026-10-06，已 45 天未演化**且一直 due。

## 三、根因
`Tools/evolve_citizen.py:due_citizens()` 中：

```python
again.sort(key=lambda c: (rank.get(c, len(rank)), c))   # 旧：rank 后按 cid 升序
```

按 cid 升序的含义是「编号小的先演化」。低段居民演化后 `next=+7 天`，7 天后重新 due 并再次排在最前；
每天 550 席预算在到达 4166 段之前就被低段复发者吃满 → **高段永久饥饿**（不是随机，是结构性）。

## 四、日覆盖分布对比（模拟 550 席/日，实测跑数）
| 排序 | 前 550 席编号段分布 | 前 550 席 last 中位 |
|---|---|---|
| 旧（cid 序） | **0–1999：550 / 550（100%）** | 2026-10-24（4 天前） |
| 新（last 序） | 2000–4999：550 / 550 | **2026-09-30（44 天前）** |

即：旧序一天之内对其他四个编号段的服务量 = **0**。

## 五、修法（R2794）
```python
again.sort(key=lambda c: (rank.get(c, len(rank)),
                          str(cursor.get(c, {}).get("last") or ""), c))
```
三键排序：①`rank`（质量修复队列，R2385 保留，仍占批头 ≤1/3）②`last` 升序（**最久未演化优先**）③`cid` 确定性兜底。

不动任何质量闸、不改阈值、不重写历史年轮、不改数据面。

## 六、效果与边界
- 验证：`py_compile` PASS；实调 `due_citizens(cursor,10)` 返回 `['C-09382','C-08933','C-04166','C-04173',…]`
  ——前两席是质量修复配额（rank 命中），其后即 45 天饿死户，符合预期。
- 全城 due=8818，按 550 席/日扫一遍需 **16.0 天**；修复后**每位居民 16 天内至少轮到一次**，
  而非「部分居民永远 0 次」。
- **诚实边界**：本修复**不增加总产出**（仍是 ~550 环/日），只改分配公平性。
  若要达到「全员 7 日一轮」，需 10114/7≈1444 环/日，为当前实测吞吐（≈550–90=实际约 552/日）的 2.6 倍——
  该缺口另案（提批/提频/换模型三选一，均需机制令），本轮不改。
